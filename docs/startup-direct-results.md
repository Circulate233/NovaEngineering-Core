# 开发客户端实机对照

客户端位于 `F:\nova\NovaEngineering-World-V2`。各轮直接运行该目录的 `mcmpu.exe runClient`。实验 JAR 用运行清单中的实际文件名放入 `debug/client/mods`，例如星核为 `stellarcore-1064321-9770337.jar`。游戏 JVM 启动后对根目录及版本子目录内的 280 个 JAR 核对 SHA-256。配置与实验覆盖层在每轮结束时恢复。逐轮使用同一套 JFR profile 和一次菜单静置后的诊断 Full GC。[采集脚本](../build/startup-test/capture.ps1) · [原版 JAR 清单](../build/startup-test/control-mods.json)

## 动画帧的真实菜单占用

此前隔离实验留下两份可重新读取的菜单 Full GC 堆转储。第 21 轮使用原版，第 23 轮同时启用 Actinium 透明像素处理的局部写回和 Nova 初次图集上传的短期借用。沿 Nova 帧、mip、编码载荷、解码窗口读取字段，按 primitive 数组对象 ID 去重。下表各字段可能指向同一数组，最后一行才是物理并集。

| 像素相关字段 | 原版（字节） | 写回与上传改版（字节） |
|---|---:|---:|
| 全部 mip 原始像素 | 60,114,736 | 10,520,304 |
| 其中已公开的 mip 原始像素 | 57,390,764 | 589,112 |
| 编码 byte[] | 4,694,070 | 18,299,878 |
| 帧的源数组 | 12,402,992 | 9,385,712 |
| 窗口中的解码数组 | 80,640 | 350,976 |
| 窗口视图数组 | 354,816 | 354,816 |
| **物理并集** | **64,889,446** | **29,171,158** |

已公开的原始像素减少 54.17 MiB，编码载荷相应增长。物理并集由 42,643 个数组减到 42,246 个，净减 **35,718,288 字节（34.06 MiB，55.05%）**。它衡量由这些字段引用的数组载荷，整个菜单 Java 堆还包含帧包装对象和其他模组。两次记录覆盖整个“写回 + 上传”组合，单个入口的独立净收益仍须单项对照。[原版逐字段结果](../build/startup-test/heap/run-21.tsv) · [改版逐字段结果](../build/startup-test/heap/run-23.tsv) · [物理数组分析程序](../build/startup-test/heap/AnimationUnion.java)
