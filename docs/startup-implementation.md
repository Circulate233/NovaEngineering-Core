# 客户端启动时间与内存优化实施决策表

后续实验直接在开发整合包内通过 mcmpu 和同名 debug JAR 做对照。原有 `F:\nova\startup-*` 采集目录已由开发者清理；下文保留对应历史数字与原路径。新采集记录，以及从仍存的两份堆转储复算出的动画数组净减 34.06 MiB，见[开发客户端实机对照](startup-direct-results.md)。

本表对应[启动时间与内存调查](startup-memory-optimization.md)。基线为 mcmpu 开发客户端、NovaEngineering-Core `522b95e6`。每项按共同调用源或共同持有者归并。实施顺序取决于重复工作是否已证实、主线程是否在等，以及其他读者是否仍持有同一份数据。R1 的 LibNine 分支、V2 的直接缓冲和 M1 的 G1 配置均已有独立实机对照。其余候选按下表列出的证据和验收条件推进。

## 第一批独立实验

| 项目与代码归属 | 选定的改法 | 能判断成败的观测 |
|---|---|---|
| R1 模型探测 · Nova 与星核 | 已验星核在一次 Forge 模型选择内共享类型和已确认的缺失。两个 loader 各查 120,221 次，进入 JSON reader 的次数从 30,014 降至 15,007。每次新选择重新查源；域白名单可能漏掉动态来源。剩余方向是在遵守包优先级的前提下，让 Nova 命中后按需开流，对同一确定来源的 JSON 共享 UVL、LibNine、CTM 各自需要的字段。 | 记录三个消费者剩余的开流、解析和主线程等待，区分模型 JSON 和纹理 .mcmeta。测试高优先级动态包晚加入、替换、F3+T、畸形 JSON、未知类型。 |
| R3 CTM 的临时烘焙 · 星核接管 bake，Nova 接管终端几何 | 先区别包装器丢弃的几何和须发布给游戏的模型，沿 multipart/weighted 传递的真实取纹理回调定位临时叶节点。只有确认当前调用实际绕过共享缓存且材质回调保持完整时才跳过最终压缩。更大的候选是给可证明纯 vanilla 子树重放有序材质回调，须先验证父模型对普通烘焙产物的读取。 | 分开数临时和最终转换、Forge 烘焙缓存复用、回调次数和 CTM 图层/贴图。重点验证 multipart、加权模型、嵌套 CTM、自定义模型和并发重载。 |
| R5 普通 PNG · 星核 | 读取一次普通精灵资源的尺寸、元数据、像素，验证格式后定向使用 PNG reader。需要自定义解码时走原路径。先测小 PNG 是否真正避免 8 KiB 缓冲，再决定 reader、缓冲封装和解码并行度。 | 每个精灵开流次数、格式探测、解码峰值缓冲与阶段墙钟。比较索引色、透明度、动画及全部 mip 像素，验证异常关闭资源。 |
| R6 动画帧 · Nova、Actinium 独立分支，兼容 HEI 和匠魂 | 先给 Actinium 的透明像素处理提供由 Nova 帧存储执行的第零级写回。曾达到现压缩门槛、只观察到此入口的公开像素为 44.0830 MiB。再给 Cleanroom.TextureMap.finishLoading 的同步图集上传加短期借用，单独涉及 0.6656 MiB，另有与 Actinium 共读的 2.1299 MiB。匠魂首帧临时复制独立计量。 | 对比 raw、编码载荷与解码窗口的物理并集。覆盖外部已持有别名、跨帧共享、所有 mip 像素、动画播放与 F3+T，分别测首次读取、菜单堆与启动阶段时间。[按数组的 JFR 归因](../../../nova/startup-resource-ab-20261125/r6-diagnostic/results.md) |
| R7 动态包补绑定 · 星核 | 将“本命名空间在本快照没有待补绑候选包”记在快照层，只有实际逐位置探测失败才存路径。 | 分解 10.92 MiB 负结果集合中的两类键，测每代条目数、补绑调用数、菜单 retained。核对增量绑定、重复注册、动态域和并发失效。 |
| V2 早期直接缓冲 · Actinium 的 GTNHLib，独立分支 | 用小型带不同标记的直接缓冲取得 NIO position/limit/capacity 字段偏移。实装三个探针各申请 219,540,062 字节，合计 628.11 MiB；保持外部调用的数据读写和缓冲身份语义。 | 核对各字段偏移、mark/reset、position/limit/capacity、slice 与浮点/整型视图；在相同客户端上比较早期 direct pool 和 NMT Other 高点、启动墙钟及建窗后渲染。 |
| M1 字符串物理数组 · 客户端 G1 配置 | 只切换 UseStringDeduplication，比较相同 coder、相同内容的额外数组。快照中这些数组占 103.63 MiB 浅大小。 | 5 GiB 客户端三对对照已完成：菜单存活堆中位数降低 93.98 MiB，去重表多提交 41.24 MiB，端到端时间变化方向不一致。按当前双目标保留默认关闭。[逐轮结果](../../../nova/startup-m1-20261125/results.md) |

R1、R3、R5 均集中在 14–15 秒的模型资源窗口。先按单项检查消除了哪些开流、遍历、转换，再测组合后的窗口与首次菜单。R6 和 M1 的优先依据来自全堆；即使菜单存活量下降，也需分别测动画首次读取与去重工作的 CPU 开销。

## 后续实验顺序

| 顺序 | 为什么选这一项 | 决定是否继续的读数 |
|---|---|---|
| 启动时间 1 · R3 CTM 临时烘焙、R5 普通 PNG，各自单测 | CTM 的临时 bakeNormal 去掉末端压实仍有 749–1,016 MiB/轮，主要成本在生成面。PNG 两次定位后还要识别格式与实际解码，图集的等待与这批工作在同一窗口。两者代码入口清晰。 | R3 比较经过 multipart/weighted 到达叶节点的临时转换数和方块烘焙墙钟。R5 比较普通 PNG 的开流、8 KiB 缓冲次数和图集准备墙钟。每项分别核对 F3+T、图集和几何，最后测两项组合能否缩短资源窗口。 |
| 启动时间 2 · B1、B6、B8，各自单测 | 这三项分布在 Construction、PreInit、配方及最后的冻结。ContentTweaker、配方事件和 PostInit 都触发脚本工作；加载画面引起一次全局刷新；冻结时主线程又经 remap 重建统计展示。 | B1 按脚本和环境统计真正重复的编译，再给纯编译结果加缓存。B6 查第一次刷新有哪些监听器立即消费结果。B8 先拆出 StatList 展示对象的物化，连同菜单前最后一段墙钟复测。 |
| 启动时间 3 · B2 HEI、R2/R4 最终模型 | HEI 的插件注册与配方建表各约两秒，tooltip 建索引还有独立工作线程。最终模型构建在多个 worker 上消耗较大，对玩家等待的影响取决于最后完成的任务。 | HEI 跟踪注册 UID、原料展开与首次搜索；模型追踪最终交付的面、变体及 writer 等待。记录主线程依赖和首次使用，逐项比较玩家等待。 |
| 菜单内存 · R6，然后 R7、M3/M4/M6 | R6 有明确物理像素和写入方；R7 的负结果集合独占 10.92 MiB。随后按所有权验证模型派生、配方/搜索、字体等对象是否能释放或共享。 | R6 以相同内容的 raw、压缩载荷、解码窗口物理并集验收，同时比较菜单 Full GC 和动画。R7 计每种失败原因的唯一键。其余按注册或最后消费时刻查实际保留，并测首用代价。 |

候选的估算只覆盖各自测到的调用或对象。R2、R3 会同时命中 FaceBakery，R5、R6 会接触同一张精灵，B8/M7 会接触同一次注册表冻结。组合收益以同一轮端点实测为准。余下 R7–R12、B3–B5、B7、B9–B10、M1–M10、V1/V2 的入口和验收均在以下清单或第一批表内。

## 配置、范围和复测

- **V1 堆提交。** 保持 8 GiB 上限，只改 Xms；比较扩堆、GC 停顿、启动峰值、静置后的提交量和首次进世界。工作集同时受 Windows 修剪影响。
- **V2 的其他归因。** 已定位的 628.11 MiB 进入第一批对照。Metaspace、Code、GC、其余直接缓冲与窗口驱动分别保留原有基线，按各自的时间和所有者验收。
- **类加载器与启动器。** L1–L5、保护域、JAR manifest 克隆和 ClassPatchManager 属已有 PR 的范围；mcmpu 保留 launcher→Java 启动计时。L6、M2 和 M9 的业务条目见上表。
- **对照方法。** 同 JDK、清单、资源、缓存状态与采集参数，以同一工作树构建并单独切换各项。实验准备阶段记录首选 OpenGL 建窗与实际回退次数。用 mcmpu 交替跑控制组和实验组，每组至少三轮，首轮额外准备单列。记录实际加载的 jar 哈希、每轮 JVM→首次菜单、受影响区间、累计分配、峰值与对应 GC、等时静置后 Full GC。项目涉及保留关系时，再用 HPROF 核对所有者。延迟工作需覆盖首次使用和 F3+T。
- **现有工作树。** Nova 的模型元数据草稿现已补齐查询判定，CTM 仅在当前叶模型确实经局部缓存烘焙时跳过压缩。使用 1.8 GiB 构建堆，Nova 工作树已通过 compileJava。这些草稿以及动画访问、星核 PNG / 负缓存尚待各自的客户端验收。M1 已在实装模组上完成配置对照。R1、R6、V2 另有[定点 JFR 调用记录](../../../nova/startup-m1-20261125/diagnostic/results.md)。
